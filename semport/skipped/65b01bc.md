## Rationale

The semantic fix — guarding `isEntityDescendant`/`isActionDescendant` walks with a
visited set so cyclic `entity Team in [Team, Application];` declarations no longer
trigger unbounded recursion — is already in place on the C# side. Our
`CedarTypeOps.IsEntityDescendant` (src/Cedar.Schema/Internal/Validate/CedarTypeOps.cs:252-282)
threads a `HashSet<EntityType>` through the recursive walk, and our
`ScopeValidator.IsActionDescendant` (src/Cedar.Schema/Internal/Validate/ScopeValidator.cs:265+)
uses an explicit stack + visited set, with an XML doc note matching upstream's defensive
rationale. The TinyTodo-shaped fixture is exercised by
`PolicyValidatorTests.ValidatePolicy_AcceptsCyclicEntityParentSchema`
(test/Cedar.Schema.Tests/PolicyValidatorTests.cs:67), which builds the same
`entity Team in [Team, Application]` schema and asserts the
`principal in Application::"app"` policy validates cleanly. Upstream's
`entity_type_parent_cycle.*` testdata adds no schema/policy semantics beyond what
that test already covers, so no additional port is needed.
