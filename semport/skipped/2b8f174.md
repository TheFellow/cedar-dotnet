## Rationale

Test-data-only fix for a Go-specific flakiness: the unguided JSON parser
on the Go side was deserializing the implicit entity form as
`types.Record`, and Go's non-deterministic map iteration order made
which validation error surfaced (and thus coverage of `checkValue`'s
`StringType` branch) flaky. No Cedar semantic change; the C# port is
not affected by Go's map iteration order, and our schema-validation
testdata (if/when ported) can use whichever form is clearest. Nothing
to port.
