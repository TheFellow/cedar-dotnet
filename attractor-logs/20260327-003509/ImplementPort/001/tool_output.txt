  13 |    - Find last occurrence of `::"` in the string
  14 |    - Index must be > 0 (type part is non-empty)

  79 | Upstream Go adds:

  82 | C# equivalent should be:
  83 | - **non-mutating** creation API (`TryParse...` / `Parse...`) because `EntityUid` is an immutable sealed record

  85 | - `FormatException` for throwing parse convenience

  89 | ## Parsing Semantics to Implement
  90 | 
  91 | Mirror the upstream Go parser behavior in `types/entity_uid.go`:
  92 | - find the **last** occurrence of `::"`
  93 | - require index `> 0` so the type portion is non-empty
  94 | - require the input to end with `"`
  95 | - split into:
  96 |   - `type = input[..idx]`
  97 |   - `id = input[(idx + 3)..^1]`
  98 | - construct:
  99 |   - `new EntityUid(new EntityType(type), new CedarString(id))`
 100 | 
 101 | ### Important scope note
 102 | The upstream Go parser is intentionally simple. It does **not** implement full Cedar string unescaping; it slices the text payload directly.
 103 | 
 104 | Therefore this port should also stay minimal unless the implementing agent explicitly chooses to widen behavior.
 105 | 
 106 | #### In-scope accepted inputs
 107 | - `User::"alice"`
 108 | - `Namespace::Type::"id"`
 109 | - `Super::"*"`
 110 | 
 111 | #### In-scope rejected inputs
 112 | - `Type::id`
 113 | - `Type"id"`
 114 | - `Type::id"`
 115 | - `Type::"id`
 116 | - `` (empty string)
 117 | - `"id"`
 118 | - `::"id"`
 119 | 
 120 | #### Explicitly out of scope unless intentionally expanded
 121 | - full Cedar string escape decoding during parse, e.g. reconstructing `a"b` back to `a"b` as a logical string value
 122 | 
 123 | This matters because current C# `MarshalCedar()` escapes via `CedarString.MarshalCedar()` (`CedarString.cs:8-10`), but there is no existing unescape helper exposed for parsing. A simple port should match upstream semantics, not invent a broader parser.

 127 | ## Recommended Implementation Sketch
 128 | 
 129 | Inside `src/Cedar.Types/EntityUid.cs`:
 130 | 
 131 | ```csharp
 132 | public static bool TryParseCedar(string input, out EntityUid? result)
 133 | {
 134 |     ArgumentNullException.ThrowIfNull(input);
 135 | 
 136 |     int idx = input.LastIndexOf("::\"", StringComparison.Ordinal);
 137 |     if (idx <= 0 || !input.EndsWith('"'))
 138 |     {
 139 |         result = null;
 140 |         return false;
 141 |     }
 142 | 
 143 |     string type = input[..idx];
 144 |     string id = input[(idx + 3)..^1];
 145 | 
 146 |     result = new EntityUid(new EntityType(type), new CedarString(id));
 147 |     return true;
 148 | }
 149 | 
 150 | public static EntityUid ParseCedar(string input)
 151 | {
 152 |     return TryParseCedar(input, out EntityUid? result)
 153 |         ? result
 154 |         : throw new FormatException($"Invalid Cedar EntityUid: '{input}'");
 155 | }
 156 | ```
 157 | 
 158 | ### Notes for the implementing agent
 159 | - Use `StringComparison.Ordinal` with `LastIndexOf(...)` for deterministic Cedar syntax parsing.
 160 | - `EndsWith('"')` is fine if available in the current target framework; otherwise use `EndsWith("\"", StringComparison.Ordinal)`.
 161 | - Keep this API static; do **not** add mutation-oriented instance APIs.
 162 | - Do not change `MarshalCedar()` or JSON converter behavior.
